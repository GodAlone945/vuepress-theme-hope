## 浏览器网络与缓存体系

网络请求通常是页面加载最大的瓶颈

1. 缓存策略决策流（面试）

   浏览器请求资源流程：

   1. 强缓存（本地）：
      - 不需要发请求给服务器
      - 核心字段：
        - `Cche-Control`：max-age=3600（HTTP/1.1，优先级高）
        -  `Expires`（HTTP/1.0，依赖本地时间，易出问题）
        - 命中表现：状态码 200（from memory cache/ from disk cache）
   2. 协商缓存（问服务器）：
      - 强缓存失效后，浏览器携带标识发送请求询问服务器：“文件变了吗？”
      - 核心字段：
        - ETag/IF-None-Match（基于文件内容哈希，最准）
        - Last-Modified/If-Modified-Since（基于修改时间，秒级精度，有误差）
      - 命中表现：服务器返回304 Not Modified（不返回包体，只返回头，省带宽）
      - 未命中：服务器返回200和新文件

2. HTTP协议的进化（解决“慢”的问题）

   - HTTP/1.1：
     - 改进：引入 Keep-Alive（长连接），减少TCP握手开销。
     - 缺陷：对头阻塞（Head-of-Line-Blocking）。如果第一个请求卡住了，后面的请求哪怕处理完了也发不回来。
   - HTTP/2：
     - 核心：多路复用（Multiplexing）。在同一个TCP连接中，通过二进制分帧（Frame），并发传输多个请求，解决了HTTP层的对头阻塞。
     - 特性：头部压缩（HPACK），服务端推送（Server Push）
     - 缺陷：依然基于TCP。如果TCP丢包，整个连接的所有流都会等待重传（TCP层的对头阻塞）
   - HTTP/3（QUIC）：
     - 核心：抛弃TCP，改用基于UDP的QUIC协议
     - 优势：真正解决了丢包阻塞的问题，连接建立速度极快（0-RTT）
